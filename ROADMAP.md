# PM Assistant — следующий эволюционный уровень

Документ описывает, куда развивать продукт после текущей версии. Он опирается
на сегодняшнюю архитектуру (vanilla JS без зависимостей, прямые вызовы Claude API
из браузера, localStorage + опциональный Supabase, деплой на GitHub Pages) и
предлагает поэтапный путь от «личного инструмента одного человека» к
«командному AI-рабочему пространству менеджера продукта».

---

## 0. Где мы сейчас (точка отсчёта)

**Что уже есть:**
- Единая карточка (заголовок, описание, персоны, проекты, приоритет, срок, теги).
- Захват свободного текста в структуру через Claude.
- Поиск на естественном языке («Спросить ассистента»).
- Проверка дублей + AI-объединение карточек (с тумблером).
- Распознавание и канонизация имён (уменьшительные → полные, уточнение ФИО).
- Доска с фильтрами/сортировкой, архив, 3 темы (тёмная/светлая/стекло).
- Облачная синхронизация между устройствами (Supabase, last-writer-wins).
- Развлекательный блок «Хочешь совет? Жми!».

**Сильные стороны:** ноль зависимостей, мгновенная загрузка, данные у пользователя,
быстрый цикл «мысль → карточка».

**Ограничения, которые задают вектор развития:**
- Один пользователь, одна «рабочая область»; нет совместной работы.
- API-ключ Claude лежит в браузере (приемлемо для себя, неприемлемо для команды).
- Синхронизация «весь документ целиком» — не масштабируется на сотни карточек
  и не разрешает конфликты при параллельной правке.
- Ассистент реактивен: отвечает на запрос, но не проявляет инициативу.
- Нет интеграций с инструментами, где реально живёт работа PM (календарь, трекеры, мессенджеры).

---

## 1. Принципы развития

1. **Сохранить скорость и приватность.** Не превращать лёгкий инструмент в тяжёлый
   SaaS без необходимости. Локальный режим остаётся первоклассным.
2. **AI — проактивный напарник, а не поле ввода.** Двигаться от «разбери текст»
   к «подскажи, напомни, подготовь за меня».
3. **Данные — собственность пользователя.** Экспорт, прозрачность, что и куда уходит.
4. **Эволюция, а не переписывание.** Каждый этап — поверх текущего кода, с обратной
   совместимостью данных (schemaVersion).

---

## 2. Дорожная карта по горизонтам

### Горизонт 1 — «Умнее и надёжнее» (1–2 месяца, без смены архитектуры)

Цель: выжать максимум из текущего стека, закрыть техдолг, усилить AI.

- **Прокси для ключа Claude (убрать ключ из браузера).** Лёгкая serverless-функция
  (Cloudflare Workers / Vercel) проксирует запросы к Anthropic; ключ живёт на
  сервере. Браузер ходит на свой прокси. Снимает главный риск безопасности и
  открывает дорогу к шерингу.
- **Стриминг ответов (SSE).** Сейчас пользователь ждёт весь ответ. Стриминг даёт
  ощущение мгновенности в поиске и генерации.
- **Кэш и дешевизна.** Prompt caching для системных промптов; не слать весь массив
  карточек в каждый запрос (клиентская предфильтрация → топ-N в модель).
- **Дельта-синхронизация.** Вместо «весь документ» — пооперационная синхронизация
  (по карточкам, с `updatedAt` и tombstone для удалений). Убирает гонки и ускоряет
  облако на больших объёмах.
- **Оффлайн-режим (PWA).** Manifest + service worker → установка на телефон/десктоп,
  работа без сети, фоновая синхронизация при появлении связи.
- **Напоминания.** Web Notifications о приближающихся/просроченных сроках.

### Горизонт 2 — «Проактивный ассистент» (3–5 месяцев)

Цель: ассистент сам приносит ценность, а не ждёт запроса.

- **Брифинг дня.** Функция `generateDailySummary()` уже написана в коде, но не
  подключена к UI. Утренняя сводка: что горит, что просрочено, на чём
  сфокусироваться, кого «пнуть». Самый быстрый высокоэффективный шаг.
- **Умная приоритизация.** Модель предлагает приоритет/срок при создании и
  подсвечивает рассинхрон («помечено P3, но дедлайн завтра»).
- **Follow-up-движок.** «Павел не прислал отчёт» → ассистент сам напомнит через
  N дней и предложит черновик сообщения.
- **Еженедельная ретроспектива.** Что сделано, что зависло, паттерны
  прокрастинации, предложения по разгрузке.
- **Голосовой ввод.** Web Speech API для захвата мыслей на ходу (особенно мобайл).
- **Связи между карточками.** Граф «карточка → проект → персона», навигация по
  контексту, авто-группировка в темы.

### Горизонт 3 — «Командное рабочее пространство» (6–12 месяцев)

Цель: от личного инструмента к инструменту команды продукта.

- **Аутентификация и роли.** Supabase Auth (magic link / OAuth). Рабочие области
  становятся настоящими, с участниками и правами.
- **Совместная работа.** Общие доски, назначение карточек, комментарии,
  @упоминания, лента активности. CRDT/OT для конфликт-фри редактирования.
- **Интеграции (где живёт работа PM):**
  - Календарь (Google/Outlook) — карточки со сроками ↔ события.
  - Трекеры (Jira/Linear/Notion) — двусторонняя синхронизация задач.
  - Мессенджеры (Slack/Telegram) — захват из сообщения, дайджесты в канал.
  - Почта — переслать письмо → карточка.
- **RAG по базе знаний.** Подключить документы команды (PRD, исследования,
  заметки встреч); ассистент отвечает со ссылками на источники.
- **Шаблоны рабочих процессов PM.** Запуск фичи, customer development, подготовка
  к ревью — преднастроенные наборы карточек и чек-листов.

### Горизонт 4 — «Агентный PM-помощник» (12+ месяцев, исследовательский)

Цель: ассистент выполняет многошаговые задачи, а не только подсказывает.

- **Agentic-задачи.** «Подготовь материалы к встрече с командой роста»: ассистент
  собирает релевантные карточки, тянет метрики из интеграций, формирует повестку
  и черновик — человек утверждает.
- **Аналитика продукта в диалоге.** Подключение к аналитике (Amplitude/Mixpanel/BQ);
  вопросы по метрикам на естественном языке с генерацией графиков.
- **Приоритизация по фреймворкам.** RICE/ICE-скоринг бэклога, what-if по дорожной карте.
- **Мультимодальность.** Скриншоты, доски Miro, PDF-исследования → карточки и выводы.

## 3. Технический план поддержки

| Область | Сейчас | Куда двигаться |
|---|---|---|
| Ключ Claude | в браузере | serverless-прокси, ключ на сервере |
| Синхронизация | весь документ, LWW | пооперационная дельта + tombstones, далее CRDT |
| Хранение | localStorage | + IndexedDB (объёмы, вложения), Supabase как источник истины |
| Доставка | статические файлы | PWA (manifest + service worker), офлайн |
| Поиск | весь массив → модель | клиентская предфильтрация + эмбеддинги + топ-N |
| Тесты | ручные + node-проверки | юнит-тесты ядра (storage/agent), e2e на критичные сценарии |
| Сборка | самописный inliner | оставить, пока нет зависимостей; модульность сохранить |

**Что осознанно НЕ меняем рано:** фреймворк (vanilla остаётся, пока не появятся
совместное редактирование/сложный стейт), систему дизайн-токенов (она уже даёт
консистентность и темы дёшево).

---

## 4. Что брать в работу первым (рекомендация)

Лучший баланс «ценность / усилия / риск» на ближайший спринт:

1. **Подключить брифинг дня** (`generateDailySummary` уже написан) — максимум
   пользы при минимуме кода; делает ассистент проактивным.
2. **Serverless-прокси для ключа** — снимает главный риск безопасности и
   разблокирует шеринг.
3. **PWA + напоминания о сроках** — ощутимый ежедневный выигрыш, особенно на мобильном.

Эти три шага превращают «аккуратный личный органайзер» в «ассистента, который
сам помогает каждый день», не ломая существующее.

---

## 5. Метрики успеха

- Скорость захвата: время «мысль → сохранённая карточка» (цель < 10 сек).
- Доля карточек, созданных из проактивных подсказок ассистента.
- Возвраты: DAU/WAU; открывается ли брифинг дня.
- Точность AI: доля принятых без правок разборов и объединений.
- Надёжность синка: конфликты/потери данных на 1000 операций (цель — ноль).

## Приложение. Технический долг и заметки ревью (текущая версия)

Замечания из код-ревью, которые стоит держать в поле зрения (часть закрыта в
этой итерации):

- **[закрыто]** Списки рендерились поэлементной вставкой в DOM → заменено на
  `DocumentFragment` (одна вставка) в `renderBoard` / `renderArchive` / поиске.
- **[закрыто]** Отсутствовали SEO/мобильные meta-теги → добавлены `description`,
  `theme-color`, `color-scheme`.
- **[закрыто ранее]** «Failed to fetch» при сетевом сбое → понятное сообщение +
  одна повторная попытка в `agent.js`.
- **Безопасность XSS:** пользовательский ввод вставляется через `textContent`
  (безопасно). Единственное `innerHTML` — статичные SVG-иконки из захардкоженного
  словаря (без пользовательских данных). Уязвимости нет; при будущем рендере
  HTML/markdown из ответов модели — экранировать.
- **Ключи в localStorage:** Claude API key и Supabase-ключи лежат в браузере.
  Для личного использования ок; для команды — вынести через прокси (Горизонт 1)
  и убрать ключ Claude с клиента.
- **Дедупликация синхронизации:** последний-записавший-побеждает на уровне всего
  документа — риск перетереть правки с другого устройства при одновременной
  работе. Решается дельта-синхронизацией (Горизонт 1).
- **Зависимость от внешнего CDN-шрифта:** `Inter` подключается из системных
  фолбэков (в CSS заданы) — при недоступности шрифта деградация корректная.
